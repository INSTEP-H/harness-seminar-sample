# Brief (작업 명세서)

이번에 만들 컨텐츠의 주제·타겟·핵심 메시지·CTA·발행 채널을 사용자와 함께 확정한다.
brief는 모든 후속 단계의 입력이므로 모호한 부분을 남기지 않는다.

## 사용법

```
/mafia-marketing:brief [<topic-slug>]
```

## 실행 방식

이 skill은 메인 컨텍스트에서 사용자와 직접 대화하며 진행한다 (sub-agent 위임 없음).
"에이전트가 이해 못 하는 부분이 있으면 사용자에게 질문하라"는 Clarify 원칙을 강하게 적용한다.

## 절차

1. 사용자에게 컨텐츠 의도 한 줄 요약을 묻는다.
2. 다음 항목을 모두 확정할 때까지 질문을 반복한다:
   - **주제 (topic)**: 한 줄로. 모호하면 "이 컨텐츠를 본 사람이 어떤 한 문장을 기억하길 바라는가?"로 좁힌다.
   - **타겟 (audience)**: 직무·상황·고민까지. "개발자"는 너무 넓다. "10명 미만 개발팀의 CTO"처럼 좁힌다.
   - **핵심 메시지 (key_message)**: 단 하나만. 두 개 이상이면 컨텐츠를 분할하도록 권한다.
   - **CTA**: 보고 나서 무엇을 하길 바라는가. 이메일 문의? URL 클릭? 댓글? 단 하나로 좁힌다.
   - **발행 채널 (channels)**: `docs/channel-formats.yaml`의 channels 중에서 선택. 다중 선택 가능.
   - **시각 자산 톤 (image_tone, optional)**: 이미지 생성 시 참고할 분위기.
3. 모호한 지점을 사용자에게 다시 던진다. 예:
   - "이 핵심 메시지는 도발형이 어울리겠는데, 어느 정도 강도로 갈지?"
   - "타겟이 개발팀 리더라면 LinkedIn이 더 맞을 것 같은데, Threads도 함께 갈지?"
4. 확정 후 `<topic-slug>`이 비어있으면 함께 결정한다 (kebab-case 권장, 날짜 prefix 가능: `2026-05-launch-week`).
5. `brief.md`를 작성한다.

## 산출물 경로

```
.content-artifacts/{topic-slug}/brief.md
```

## 문서 구조

```markdown
# Brief — {topic-slug}

## 주제 (topic)
한 줄로.

## 핵심 메시지 (key_message)
이 컨텐츠가 전달하는 단 하나의 메시지.

## 타겟 (audience)
직무 · 상황 · 고민.

## CTA
이 컨텐츠를 본 사람이 다음에 할 단 하나의 행동.

## 발행 채널 (channels)
- threads
- linkedin

## 시각 자산 톤 (image_tone)
- (자유 텍스트, 선택)

## 참고/금지
- 참고: ...
- 금지: ...

## 모호한 지점 (사용자 확인 완료)
- Q-1. ... → 결정: ...
```

## 제약

- 핵심 메시지는 반드시 **단 하나**여야 한다. 두 개 이상이면 컨텐츠 분할을 권한다.
- 타겟이 모호하면 다음 단계로 넘기지 않는다.
- brief 자체에는 본문 초안을 쓰지 않는다. 본문은 draft 단계의 책임이다.
